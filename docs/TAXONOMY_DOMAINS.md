## 2. Classifier — 3 ชั้น deterministic (viewer-side, ไม่แตะ data)

`classifyLaw(law)` ใน `demo/public/index.html` (single source; audit copy = harness เดียวกัน):

1. **DOM_EXC** — exception รายฉบับ keyed ด้วย `law_code` (ห้าม key ด้วย lNNNN — reassigned ทุก rebuild)
2. **DOM_PREFIX** — family ตามรหัสเรื่องของกฤษฎีกา (ป0003→แพ่ง, ป0008→ภาษี, ว0085→เวนคืน→ที่ดิน, ม0032/34/36→ครุย→การศึกษา, …) ~26 prefix ≈ 300 ฉบับ
3. **DOM_KW** — keyword วลียาว **เรียงลำดับ = กติกาตัดสิน** (first match wins):
   ศาล/วิธีพิจารณา → ภาษี → แรงงาน-สวัสดิการ → ที่ดิน → เงินเดือน(กันชื่อองค์กร) → อาญา → คมนาคม(ก่อนทหาร กัน "ระหว่างประเทศ") → ทหาร-ตปท → สาธารณสุข → การศึกษา → สิ่งแวดล้อม-เกษตร → ธุรกิจ → รัฐธรรมนูญ → ปกครอง(กว้าง, ท้าย) → แพ่ง
4. ไม่เข้าอะไรเลย → **"ยังไม่จัดหมวด"** แสดงเป็นหมวดจริงพร้อมจำนวน — ไม่ยัดมั่ว ไม่ซ่อน

**Override contract (รอ C):** ถ้า `laws.json` มี field `domain`/`subject` ในอนาคต → ใช้ค่านั้นก่อน rule ทุกชั้น (โค้ดรองรับแล้ว: `law.domain ?? classifyLaw(law)`)

## 3. กติกาชื่อกำกวม (LLM ภายนอก + audit จริง 3 รอบ)

- จัดตั้งศาลX / แผนกคดีX → ศาล (โครงสร้างอำนาจชนะเนื้อเรื่อง)
- ภาษีที่ดิน → ภาษี (กลไกจัดเก็บชนะทรัพย์ที่ถูกเก็บ)
- เวนคืนเพื่อสร้างทางหลวง → ที่ดิน (หัวใจ = อำนาจเหนืออสังหาฯ; ที่ดินยิงก่อนคมนาคม)
- ธนาคารเพื่อการเกษตร → ธุรกิจ-การเงิน (สถาบันการเงินชนะภาคเกษตร)
- พรฎ.เงินเดือนกรรมการ ป.ป.ช. → ปกครอง (กฎหมายค่าตอบแทน ไม่ใช่กฎหมายปราบทุจริต — rule เงินเดือนยิงก่อนอาญา)
- รับขนทางอากาศระหว่างประเทศ → คมนาคม (คมนาคมยิงก่อนทหาร-ตปท)
- นิรโทษกรรม/ล้างมลทิน/อภัยโทษ → ยุติธรรม (การลบล้างโทษ = กระบวนการยุติธรรม)
- ประกาศคณะปฏิวัติ "ฉบับที่ N" (ไม่มีเรื่องในชื่อ) → ยังไม่จัดหมวด โดยเจตนา (จะแม่นต้องอ่านตัวบท = งานรอบหน้า)
